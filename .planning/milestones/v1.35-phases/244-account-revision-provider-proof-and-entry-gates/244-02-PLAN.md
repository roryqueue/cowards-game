Output: A Go readiness helper, focused tests, and account-save integration for TypeScript/Python/Rust/Zig provider-proof-backed readiness.
</objective>

<threat_model>
## Trust Boundaries

| Boundary | Description |
| --- | --- |
| account request -> Go save route | Authenticated user submits hostile Strategy source for account-owned revision storage. |
| Go save route -> runtime-service | Go asks provider boundary for validation/proof and verifies the returned identity. |
| Go save route -> PostgreSQL | Only proof-backed ready rows or explicit non-execution draft rows may be persisted. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
| --- | --- | --- | --- | --- |
| T-244-02-01 | Spoofing | readiness labels | mitigate | Labels derive from provider proof and registry policy, not source format or local language assumptions. |
| T-244-02-02 | Tampering | stored revision metadata | mitigate | Verify source/artifact identity and provider proof before setting execution-ready or entry-eligible state. |
| T-244-02-03 | Repudiation | invalid/unavailable saves | mitigate | Persist invalid proof only as explicit non-execution evidence; fail closed on system/proof corruption. |
| T-244-02-04 | Information disclosure | account-save errors | mitigate | Normalize public categories and deny D-10 private markers in tests. |
| T-244-02-05 | Elevation of privilege | Go account save | mitigate | Do not execute or compile Strategy code in Go/web/API; runtime-service remains the hostile-code boundary. |
</threat_model>
