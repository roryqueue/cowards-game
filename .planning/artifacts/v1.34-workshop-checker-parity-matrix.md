## Required Phase 239+ Fix Set

Phase 239 should implement:

1. A shared Workshop checker envelope at `/api/workshop/validate`.
2. Provider-grade Python Validate source semantics matching submit/save.
3. Schema validation and public-safe normalization of runtime-service validation responses.
4. Distinct runtime-service unavailable and toolchain unavailable states.
5. Public-safe artifact/provenance/provider proof state without artifact bytes or raw diagnostics.

Phase 240 should implement:

1. Python/Rust/Zig diagnostic category mapping.
2. Calm unavailable-state copy.
3. UI display changes for public-safe categories and actionability.

Phase 241 should implement:

1. Cache identity and stale result prevention.
2. Rust/Zig validation debounce/coalescing/cache behavior.
3. Boundary monitors for no Strategy execution in web/API/Go and no TinyGo production leakage.

Phase 242 should prove:

1. Four-language service-backed checker E2E.
2. Submit/save/entry parity coverage.
3. Privacy scans and milestone audit.

## No-Change Baseline

- TypeScript remains the practical Workshop UX baseline.
- Runtime-service / Runtime Broker / provider boundaries remain the hostile-code boundary.
- Submit/save/entry gates remain authoritative; checker output is preflight guidance.
- Rust/Zig remain immutable WASM/WASI Preview 1 artifact-backed lanes.
- TypeScript/Python artifact provenance remains provenance evidence, not WASM isolation or sandbox certification.
