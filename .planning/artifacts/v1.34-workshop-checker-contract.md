# v1.34 Workshop Checker Public Contract

**Phase:** 238 - Workshop Checker Path Inventory and Public Contract
**Date:** 2026-06-01
**Status:** Contract for Phase 239+ implementation

## Purpose

The Workshop checker contract gives all production Strategy languages the same public-safe validation shape before submit/save/entry. It is a diagnostic and readiness contract, not a new runtime ownership claim. Hostile Strategy validation/build behavior remains behind runtime-service / Runtime Broker / provider boundaries where provider-grade semantics are required.

## Supported Production Languages

Only these source formats are in the production checker contract:

- `typescript`
- `python`
- `rust`
- `zig`

TinyGo remains spike-only and must not appear in production Workshop checker, submit/save, entry, result, replay, or public evidence surfaces.

## Diagnostic Categories

Shared categories:

- `source_too_large`
- `syntax_or_parse`
- `strategy_api_shape`
- `forbidden_capability`
- `forbidden_import`
- `package_or_dependency`
- `compile_failed`
- `artifact_missing`
- `artifact_stale`
- `artifact_mismatch`
- `provenance_missing`
- `provenance_mismatch`
- `provenance_unverifiable`
- `provider_proof_invalid`
- `runtime_service_unavailable`
- `toolchain_unavailable`
- `timeout_or_limit`
- `invalid_output_schema`
- `unsupported_provider`
- `system_unavailable`

Language-specific expectations:

- Python diagnostics must distinguish policy/capability, forbidden import, package/dependency, syntax/build, provenance, runtime-service unavailable, timeout/limit, and invalid output/schema categories.
- Rust diagnostics must distinguish compile, artifact/provenance, forbidden WASI/import, runtime-service, toolchain unavailable, timeout/limit, and invalid output/schema categories.
- Zig diagnostics must distinguish compile, artifact/provenance, forbidden WASI/import, no-std/helper misuse, runtime-service, toolchain unavailable, timeout/limit, and invalid output/schema categories.
- TypeScript diagnostics should retain the current practical quality while adding contract metadata and public-safe categories.

## Status Semantics

- `ready`: Provider-grade validation passed for the current source and source format.
- `invalid`: Source was checked and failed a user-actionable source/policy/API/compile/artifact/provenance rule.
- `stale`: Displayed check result does not match the current source, source format, provider contract, runtime ABI, toolchain key, validation policy, or artifact identity.
- `runtime_service_unavailable`: Runtime-service was required but unavailable or returned an unavailable/system category. This state should be calm: the Strategy is not judged unsafe or broken.
- `toolchain_unavailable`: The required provider toolchain is unavailable or misconfigured. This state should be calm and actionable.
- `system_unavailable`: Storage, network, malformed service envelope, or other non-Strategy system condition blocked checking.
- `checking` and `not_checked`: UI/client transient states; server responses normally return one of the checked states above.

## Cache Identity Rules

A cached checker response can be reused only when all applicable identity fields match:

- language id
- provider id
- source hash
- source byte count
- artifact hash and artifact byte count when present
- provider contract version
- runtime ABI version
- validation policy
- toolchain key or toolchain compatibility metadata

Rust and Zig caches must be invalidated on toolchain/provider compatibility changes. No cache may cross language, provider, source hash, artifact hash, or validation policy boundaries.

## Public-Safe Privacy Rules

Default/public checker output must never expose:

- Strategy source.
- StrategyMemory or SoldierMemory.
- Objective payloads.
- Raw compiler diagnostics.
- Raw runtime diagnostics.
- Artifact bytes or encoded artifact payloads.
- Host paths.
- Environment values.
- Package paths.
- Tokens, secrets, or signing proofs.
- Database details.
- Private runtime internals.
- Operator, quarantine, or recovery payloads.

Allowed by default:

- normalized diagnostic category
- public-safe message
- public-safe constraint/remediation/reference
- source hash and byte count
- artifact hash and byte count when useful as provenance evidence
- provider id and contract version
- runtime ABI version and ABI posture
- public availability state

## Ownership and Non-Claims

- Web/API/Go may transport and display checker responses but must not execute Strategy source or compile hostile artifacts.
- Runtime-service / Runtime Broker / provider boundary owns hostile validation/build semantics for provider-grade checks.
- TypeScript and Python source artifacts are provenance evidence only; they are not WASM isolation or production sandbox certification.
- Rust and Zig remain immutable WASM/WASI Preview 1 artifact-backed lanes.
- The checker contract does not replace submit/save/entry gates. It gives users accurate preflight diagnostics and should align with those gates.
