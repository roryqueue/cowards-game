# Core Rules, Enforcement, Runtime, and Metagame Audit

**Reviewed:** 2026-07-12

**Reviewed snapshot:** [`38f4a83db9298502c12db44cd66d026878803d20`](https://github.com/roryqueue/cowards-game/tree/38f4a83db9298502c12db44cd66d026878803d20)

**Status:** Findings captured; no fixes or rule changes are implied by this document

**Follow-on proposal:** [v2.0 Rules Integrity and Metagame Renewal](../milestone-proposals/v2.0-rules-integrity-and-metagame-renewal/PROPOSAL.md)

**Reproduction artifacts:** [v2.0 core-rules audit artifacts](../artifacts/v2.0-core-rules-audit/README.md)

## Questions evaluated

This audit examined:

- whether written core rules and implemented behavior agree;
- whether all rules are enforced correctly and intuitively;
- whether runtime language can change gameplay consequences;
- which rules add complexity without meaningful play;
- which minimal changes could improve fun and practical counterplay;
- whether the present benchmark supports a long-term anti-meta claim.

The review covered the canonical v1 rules, the v1.4 Cycle-interleaving amendment, engine transitions, spec schemas, Chronicle construction and validation, runtime-service behavior, TypeScript/Python/WASM adapters, map definitions, Strategy libraries, competition evidence, and focused empirical probes.

## Executive verdict

The tactical kernel is strong and mostly coherent for valid canonical state. Setup, Round activation counts, alternating initiative, Cycle-layer snake scheduling, MOVE/PUSH resolution, simultaneous Backstab discovery, no-Advance stoning, Contraction, and active-count outcomes have real implementation and test coverage.

The system is not yet a closed rules authority:

- gameplay and Chronicle generation duplicate the full Match loop;
- schemas accept impossible semantic states;
- Chronicle grammar does not track each interleaved slot independently;
- equivalent runtime failures can receive different gameplay classifications by language;
- declared four-language parity is substantially broader than the executable proof;
- several current rules are ambiguous or exist only in code;
- the current mirrored MatchSet construction swaps side and initiative together, so the same entrant can retain first initiative;
- the current benchmark population and arena pool are not independent enough to establish durable counterplay;
- the current action budget lets the tactical microgame crowd out the Contraction macrogame.

A literal guarantee of “no long-term meta” is impossible for a frozen deterministic finite game. The defensible target is **practical anti-dominance**: every leading pure Strategy has a robust counter in sealed mirrored evaluation, the top best-response graph has no singleton sink, and versioned arena variation rewards general doctrines rather than board scripts.

## Confirmed enforcement and authority findings

### F-01 — Two full Match loops can drift

`runMatch` and `buildChronicleFromMatch` independently implement the Phase/Round/Contraction loop: [engine Match loop](https://github.com/roryqueue/cowards-game/blob/38f4a83db9298502c12db44cd66d026878803d20/packages/engine/src/match.ts#L100-L145) and [Chronicle builder loop](https://github.com/roryqueue/cowards-game/blob/38f4a83db9298502c12db44cd66d026878803d20/packages/replay/src/build.ts#L185-L260). Runtime-service uses the Chronicle builder path directly ([execute-match.ts](https://github.com/roryqueue/cowards-game/blob/38f4a83db9298502c12db44cd66d026878803d20/apps/runtime-service/src/execute-match.ts#L462-L474)).

This is the central authority risk: engine-only tests can pass while service-produced evidence follows a different loop. v2 should have one transition driver; Chronicle construction should record its transitions rather than reimplement them.

### F-02 — Runtime failure classification is not language-neutral end to end

The shared ABI distinguishes `runtimeViolation` from `systemFailure` ([runtime contract](https://github.com/roryqueue/cowards-game/blob/38f4a83db9298502c12db44cd66d026878803d20/packages/spec/src/runtime.ts#L383-L412)). The Python adapter maps every system failure to player violation `THROWN_EXCEPTION` ([Python normalizers](https://github.com/roryqueue/cowards-game/blob/38f4a83db9298502c12db44cd66d026878803d20/packages/runtime-python/src/python-subprocess-adapter.ts#L320-L379)); the WASM/WASI adapter does the same ([WASM/WASI normalizers](https://github.com/roryqueue/cowards-game/blob/38f4a83db9298502c12db44cd66d026878803d20/packages/runtime-wasm-wasi/src/wasm-wasi-subprocess-adapter.ts#L311-L370)). The engine runtime result itself has only success or gameplay violation ([engine runtime type](https://github.com/roryqueue/cowards-game/blob/38f4a83db9298502c12db44cd66d026878803d20/packages/engine/src/types.ts#L74-L81)).

Equivalent infrastructure failures can therefore stone a Soldier or otherwise penalize a player in one lane while aborting or classifying differently in another. A central three-way invocation boundary is required; adapters must transport classification, not decide gameplay.

### F-03 — Valid-size deeply nested memory can throw during “safe” validation

The recursive JSON schema has no explicit depth or node limit ([schemas.ts](https://github.com/roryqueue/cowards-game/blob/38f4a83db9298502c12db44cd66d026878803d20/packages/spec/src/schemas.ts#L42-L53)). A 3,000-deep nested array serializes below the current StrategyMemory byte ceiling yet produced `RangeError: Maximum call stack size exceeded` instead of a typed invalid-output result.

Canonical JSON needs finite-number, safe-integer, negative-zero, Unicode, duplicate-key, depth, node, and byte rules, with iterative preflight and exception containment shared by all lanes.

### F-04 — No-Advance cleanup can eliminate the final Soldier without ending immediately

`closeSlot` can stone a Soldier but does not apply the Match outcome ([activation.ts](https://github.com/roryqueue/cowards-game/blob/38f4a83db9298502c12db44cd66d026878803d20/packages/engine/src/activation.ts#L227-L260)). Focused reproduction left the last Soldier `STONE`, returned no outcome, and emitted no `MATCH_ENDED`. Later scheduling eventually repairs the winner but emits counterfactual skipped events and violates immediate termination semantics.

Every status-changing operation must be followed by the same outcome transition.

### F-05 — Cycle-end Backstab can leave a STONE actor’s slot open

Post-Backstab termination is derived from Action/exhaustion state without re-reading the actor’s status ([activation.ts](https://github.com/roryqueue/cowards-game/blob/38f4a83db9298502c12db44cd66d026878803d20/packages/engine/src/activation.ts#L493-L545)). The focused probe produced a STONE actor with `ended: false` and no terminal reason. At the exhaustion boundary the same shape can be mislabeled `CYCLE_EXHAUSTED`.

The rules also need an explicit ruling for “actor became STONE/FALLEN during its Cycle-end Backstab scan.”

### F-06 — “Excess orders are ignored” has undefined and surprising precedence

The complete Strategy result is validated before the order list is filtered/capped ([selection validation](https://github.com/roryqueue/cowards-game/blob/38f4a83db9298502c12db44cd66d026878803d20/packages/engine/src/activation.ts#L139-L197)); filtering happens through a separate prefix/filter path ([activation.ts](https://github.com/roryqueue/cowards-game/blob/38f4a83db9298502c12db44cd66d026878803d20/packages/engine/src/activation.ts#L63-L88)). A malformed second order in Round 1 invalidated the valid first order, even though the second was nominally excess.

The v2 specification must choose and test one literal precedence: cap raw orders then validate the relevant prefix, or require every supplied order to be valid before excess entries are ignored.

### F-07 — Arena and successful-final-state schemas certify impossible states

Arena bounds and terrain receive mostly shape validation ([BoardBounds/Arena schemas](https://github.com/roryqueue/cowards-game/blob/38f4a83db9298502c12db44cd66d026878803d20/packages/spec/src/schemas.ts#L277-L287), [ArenaVariant schema](https://github.com/roryqueue/cowards-game/blob/38f4a83db9298502c12db44cd66d026878803d20/packages/spec/src/schemas.ts#L2020-L2025)). A terrain square overlapping a canonical starting Soldier was accepted.

The execution final-state schema is also shape-oriented ([final-state schema](https://github.com/roryqueue/cowards-game/blob/38f4a83db9298502c12db44cd66d026878803d20/packages/spec/src/schemas.ts#L2391-L2441)). It can accept duplicate occupancy, unknown owners, incompatible status/position, bad initiative, inverted bounds, or a “successful” nonterminal state. Semantic refinements must validate identities, occupancy, status-position consistency, bounds, terrain, Round/activation mapping, versions, and outcome.

### F-08 — Chronicle grammar does not track interleaved slots independently

The grammar defines one optional `activeActivation` ([grammar state](https://github.com/roryqueue/cowards-game/blob/38f4a83db9298502c12db44cd66d026878803d20/packages/replay/src/grammar.ts#L10-L24)), sets it back to `undefined` on `ACTIVATION_STARTED`, and repeatedly discards returned activation context ([grammar transitions](https://github.com/roryqueue/cowards-game/blob/38f4a83db9298502c12db44cd66d026878803d20/packages/replay/src/grammar.ts#L559-L705)). Mutating all Cycle-1 events for one slot to Cycle 5, creating duplicate/out-of-order Cycle 5 events, still validated.

Chronicle v2 needs a per-`activationId` state machine that tracks each open slot’s next Cycle independently.

### F-09 — Active v1.4 Chronicles accept historical Backstab boundaries

The event schema admits `activation-start`, `activation-end`, and `post-advance` alongside v1.4 values ([schemas.ts](https://github.com/roryqueue/cowards-game/blob/38f4a83db9298502c12db44cd66d026878803d20/packages/spec/src/schemas.ts#L2226-L2241)). Version validation checks the Chronicle version tuple but does not restrict those payload literals by version ([validate.ts](https://github.com/roryqueue/cowards-game/blob/38f4a83db9298502c12db44cd66d026878803d20/packages/replay/src/validate.ts#L93-L110)). Changing a valid `chronicle-v1.4` Backstab event to `post-advance` still validated, contrary to the active v1.4 timing rule ([v1.4 prohibition](https://github.com/roryqueue/cowards-game/blob/38f4a83db9298502c12db44cd66d026878803d20/CowardsGameSpec_CycleInterleaved_v1.4.md#L72-L90)).

Historical decoding should remain available only through explicit versioned parsing; it must not broaden newly produced v1.4/v2 evidence.

### F-10 — A stale contiguous-Activation entry point remains public

Production Round scheduling correctly uses Cycle-layer execution, but `resolveActivation` remains exported as a contiguous wrapper ([activation.ts](https://github.com/roryqueue/cowards-game/blob/38f4a83db9298502c12db44cd66d026878803d20/packages/engine/src/activation.ts#L551-L592), [engine index](https://github.com/roryqueue/cowards-game/blob/38f4a83db9298502c12db44cd66d026878803d20/packages/engine/src/index.ts#L1-L8)). Its continued public availability creates an easy path for future code or tests to enforce historical sequencing.

### F-11 — Several gameplay rulings are ambiguous or implementation-only

- **Same-direction collision:** the engine blocks a mover approaching a Soldier from behind ([movement.ts](https://github.com/roryqueue/cowards-game/blob/38f4a83db9298502c12db44cd66d026878803d20/packages/engine/src/movement.ts#L67-L100)), while the prose specifies opposite-facing head-to-head and perpendicular side-push cases but not this third orientation ([collision rules](https://github.com/roryqueue/cowards-game/blob/38f4a83db9298502c12db44cd66d026878803d20/CowardsGameSpec_Full_Consolidated_v1.md#L730-L777)).
- **Push/reversal history:** a successful push updates the pusher’s history but preserves the pushed Soldier’s history ([movement.ts](https://github.com/roryqueue/cowards-game/blob/38f4a83db9298502c12db44cd66d026878803d20/packages/engine/src/movement.ts#L120-L132)). The prose can be read as saying either no push updates history or only forced displacement does not ([movement history rules](https://github.com/roryqueue/cowards-game/blob/38f4a83db9298502c12db44cd66d026878803d20/CowardsGameSpec_Full_Consolidated_v1.md#L681-L706)).
- **Backstab attacker orientation:** current rules and implementation use the victim’s rear square but ignore attacker facing ([backstab.ts](https://github.com/roryqueue/cowards-game/blob/38f4a83db9298502c12db44cd66d026878803d20/packages/engine/src/backstab.ts#L16-L35)). Literal and implemented behavior agree, but many readers will infer that an attacker must face its victim.
- **Initiative visibility:** initiative is described as meaningful but is not present in Strategy input ([runtime inputs](https://github.com/roryqueue/cowards-game/blob/38f4a83db9298502c12db44cd66d026878803d20/packages/engine/src/runtime-inputs.ts#L52-L84)).

Each orientation/timing case should appear in an exhaustive prose table and executable example.

### F-12 — Event vocabulary and constant ownership can drift

`PUSH_ATTEMPTED` exists in the canonical event vocabulary/schema but movement emits only resolved/blocked effects ([movement events](https://github.com/roryqueue/cowards-game/blob/38f4a83db9298502c12db44cd66d026878803d20/packages/engine/src/movement.ts#L101-L152), [event types](https://github.com/roryqueue/cowards-game/blob/38f4a83db9298502c12db44cd66d026878803d20/packages/spec/src/types.ts#L470-L492)). Either emit it or remove it.

Initial state construction aliases nested values from mutable runtime constants ([state.ts](https://github.com/roryqueue/cowards-game/blob/38f4a83db9298502c12db44cd66d026878803d20/packages/engine/src/state.ts#L44-L105), [constants.ts](https://github.com/roryqueue/cowards-game/blob/38f4a83db9298502c12db44cd66d026878803d20/packages/spec/src/constants.ts#L28-L48)). Mutating one returned state can affect a later initial state. Clone/freeze canonical values and prove output-mutation isolation.

## Confirmed cross-language drift opportunities

### F-13 — The four-language gate declares much more than it executes

The test declares thirteen required gates for all four languages ([four-language parity test](https://github.com/roryqueue/cowards-game/blob/38f4a83db9298502c12db44cd66d026878803d20/apps/runtime-service/src/four-language-parity.test.ts#L140-L165)), then executes a single `first-active-turn-to-stone` behavior across pairings and compares final outcome plus presence of broad event types ([same test](https://github.com/roryqueue/cowards-game/blob/38f4a83db9298502c12db44cd66d026878803d20/apps/runtime-service/src/four-language-parity.test.ts#L167-L231)). It does not execute the declared invalid-output, timeout, oversized, forbidden-capability, memory-heavy, deterministic-repeat, runtime-unavailable, malformed-result, or stale-artifact corpus across all lanes, and it does not compare full state/event/memory traces.

Counted parity should derive from a real conformance artifact hash. A declared gate name is not evidence.

### F-14 — Python source normalization and revision identity can disagree

Python artifacts normalize CRLF/CR to LF before building artifact bytes ([validation.ts](https://github.com/roryqueue/cowards-game/blob/38f4a83db9298502c12db44cd66d026878803d20/packages/runtime-python/src/validation.ts#L27-L48)), while execution passes the revision’s original source hash into the normalized artifact path ([Python adapter](https://github.com/roryqueue/cowards-game/blob/38f4a83db9298502c12db44cd66d026878803d20/packages/runtime-python/src/python-subprocess-adapter.ts#L381-L458)). A valid CRLF-authored source can therefore fail identity checks on every call.

The contract must define whether identity is over original bytes or canonicalized bytes, store both only when necessary, and compare the correct identity consistently.

### F-15 — Current counted TypeScript containment should fail closed pending proof

The registry allows counted results on the worker-thread adapter while explicitly labeling its isolation evidence-only and not a final hostile-code boundary ([runtime registry](https://github.com/roryqueue/cowards-game/blob/38f4a83db9298502c12db44cd66d026878803d20/packages/spec/src/runtime.ts#L1116-L1135)). Source filtering is pattern-based ([validation.ts](https://github.com/roryqueue/cowards-game/blob/38f4a83db9298502c12db44cd66d026878803d20/packages/runtime-js/src/validation.ts#L12-L40)), and the worker imports generated Strategy module source before completing all constructor hardening ([worker harness](https://github.com/roryqueue/cowards-game/blob/38f4a83db9298502c12db44cd66d026878803d20/packages/runtime-js/src/worker-harness.ts#L146-L193)). Defensive probing confirmed that valid-looking source can reach nondeterministic host capability. Reproduction details are intentionally omitted here.

This is an eligibility/containment finding, not a claim that worker threads can be made into production isolation through more regexes. New counted scheduling should refuse this lane until the approved threat model and executable abuse corpus pass.

## Game-design and metagame findings

### F-16 — The first Phase strongly rewards compulsory evacuation

All eight Soldiers start on the outer rows ([starting setup](https://github.com/roryqueue/cowards-game/blob/38f4a83db9298502c12db44cd66d026878803d20/CowardsGameSpec_Full_Consolidated_v1.md#L221-L265)), which are removed at the first Contraction ([contraction rules](https://github.com/roryqueue/cowards-game/blob/38f4a83db9298502c12db44cd66d026878803d20/CowardsGameSpec_Full_Consolidated_v1.md#L899-L935)). A player receives only ten activation-selection slots across Rounds 1–4. Preserving all eight Soldiers therefore spends at least eight slots on evacuation. The shared Advanced generator encodes this pressure as a dominant `unmoved * 1000` selection priority ([advanced-strategies.ts](https://github.com/roryqueue/cowards-game/blob/38f4a83db9298502c12db44cd66d026878803d20/packages/persistence/src/advanced-strategies.ts#L127-L145)).

Moving starts inward is worth testing, but it is not automatically free: it can make unselected ACTIVE reserves safely survive and strengthen turtling. Test it independently from Cycle and movement changes.

### F-17 — Action throughput crowds out the Contraction macrogame

With ten selected slots per Phase and twelve Cycles per slot, each player can emit up to 120 Actions per Phase. The final v1.5 corpus recorded 7,662 Cycles, 7,103 Advances, and only 31 Contractions in 33 Matches—about 0.94 Contractions per Match ([v1.5 verification](https://github.com/roryqueue/cowards-game/blob/38f4a83db9298502c12db44cd66d026878803d20/.planning/milestones/v1.5-phases/37-demo-and-regression-verification/37-VERIFICATION.md#L61-L64)). That corpus also recorded zero blocked moves, zero direct TURN_TO_STONE, and zero off-board Moves.

The correct experiment is no longer “adopt cap 4, use 6 only if it fails.” Geometry shows that cap 4 with current outer-row starts guarantees no Round-1 contact, while cap 6 preserves Round-1 contact and halves the action ceiling. The safe ablation is `12 → 8 → 6 → 5 → 4`, with cap 6 as the first serious challenger and cap 4 treated as a deployment-Round stress test. See [the proposal’s experiment protocol](../milestone-proposals/v2.0-rules-integrity-and-metagame-renewal/PROPOSAL.md#revised-cycle-cap-experiment).

### F-18 — Backstab is universal competence, but attacker-facing is not an obvious nerf

All Advanced profiles are told to take immediate rear-square opportunities ([advanced-strategies.ts](https://github.com/roryqueue/cowards-game/blob/38f4a83db9298502c12db44cd66d026878803d20/packages/persistence/src/advanced-strategies.ts#L57-L76)), and the v1.5 corpus averaged roughly 12.5 Backstab resolutions per Match.

Requiring the attacker to face the victim preserves ordinary self-propelled rear ingress: a Soldier entering the rear square from directly behind already faces toward the victim because successful MOVE updates facing ([movement.ts](https://github.com/roryqueue/cowards-game/blob/38f4a83db9298502c12db44cd66d026878803d20/packages/engine/src/movement.ts#L193-L209)). It mainly removes accidental kills caused by a victim TURN, a push-created relationship, or an attacker already behind while facing elsewhere. Under a separate facing-only MOVE experiment, however, flanking consumes extra TURN budget and the combined change could suppress Backstab too far.

The experiment must therefore split two independent questions: first remove redundant Cycle-start scans while preserving current geometry; only then compare attacker-facing under both current and facing-only MOVE. It is a hypothesis, not a presumed win.

### F-19 — The Advanced library overstates strategic independence

All ten definitions are emitted by one shared generator. Several profile labels do not correspond cleanly to behavior: wall logic is mostly shared, `trapBias` rewards contact more than trap construction, and nominally stateless doctrines still read shared memory paths ([generator scoring](https://github.com/roryqueue/cowards-game/blob/38f4a83db9298502c12db44cd66d026878803d20/packages/persistence/src/advanced-strategies.ts#L88-L145), [brain/memory logic](https://github.com/roryqueue/cowards-game/blob/38f4a83db9298502c12db44cd66d026878803d20/packages/persistence/src/advanced-strategies.ts#L171-L205)).

The library is useful regression input, not independent evidence that the rules generate diverse doctrines.

### F-20 — Current arenas and seeds provide nominal rather than real scenario diversity

Smoke and Open Field are both empty 12×12 geometries ([map configs](https://github.com/roryqueue/cowards-game/blob/38f4a83db9298502c12db44cd66d026878803d20/packages/map-configs/src/index.ts#L5-L31)). Only Standard Cross is geometrically distinct. Arena definitions are then duplicated in persistence seed data ([seed.ts](https://github.com/roryqueue/cowards-game/blob/38f4a83db9298502c12db44cd66d026878803d20/packages/persistence/src/seed.ts#L96-L120)), Go presets and arena construction ([live_backend.go](https://github.com/roryqueue/cowards-game/blob/38f4a83db9298502c12db44cd66d026878803d20/apps/go-backend/live_backend.go#L3229-L3314)), and UI IDs ([replay-ready.ts](https://github.com/roryqueue/cowards-game/blob/38f4a83db9298502c12db44cd66d026878803d20/apps/web/app/matches/replay-ready.ts#L107-L111)). Repository search found no production consumer of `curatedArenaVariants` outside its package test, so the nominal canonical package is not yet the actual authority.

The engine seed affects initial initiative through a parity-like hash choice ([state.ts](https://github.com/roryqueue/cowards-game/blob/38f4a83db9298502c12db44cd66d026878803d20/packages/engine/src/state.ts#L19-L31)); same-initial-initiative seeds otherwise describe the same deterministic scenario.

Official evidence should use explicitly versioned initiative/scenario identities and genuinely distinct symmetry-balanced arenas rather than implying broader randomness.

### F-21 — Existing competition demonstrations are not balance proof

The shipped v1.5 Advanced demonstration runs one side and one Smoke arena per pair ([demo script](https://github.com/roryqueue/cowards-game/blob/38f4a83db9298502c12db44cd66d026878803d20/scripts/run-v1-5-advanced-demo.ts#L305-L393)). The historical 23–1 Backstab Hunter result was pod-local because the ladder splits entrants into pods ([ladder scheduler](https://github.com/roryqueue/cowards-game/blob/38f4a83db9298502c12db44cd66d026878803d20/packages/persistence/src/ladder.ts#L1055-L1105)). Neither result establishes field-wide dominance or counterplay.

The audit’s 540-Match current-rules matrix mirrored sides, both initiative parities, and all three configured arenas. Stonewall Shear and Vanguard Pressure each finished 62–44–2 (57.4%); nine majority-edge three-cycles existed below them, but neither leader had a majority-losing matchup. Smoke/Open Field records were identical. This suggests useful mid-field non-transitivity plus a possible two-profile plateau—not a proven healthy top meta.

### F-22 — Current MatchSet mirroring can preserve the same entrant’s initiative

The written Set rule promises alternating initial initiative ([full rules](https://github.com/roryqueue/cowards-game/blob/38f4a83db9298502c12db44cd66d026878803d20/CowardsGameSpec_Full_Consolidated_v1.md#L1307-L1310)). MatchSet construction swaps entrant sides and appends `:mirror` to the seed ([matchset-service.ts](https://github.com/roryqueue/cowards-game/blob/38f4a83db9298502c12db44cd66d026878803d20/packages/persistence/src/matchset-service.ts#L65-L86)); the competition and Go paths repeat the pattern ([competition.ts](https://github.com/roryqueue/cowards-game/blob/38f4a83db9298502c12db44cd66d026878803d20/packages/persistence/src/competition.ts#L481-L506), [live_backend.go](https://github.com/roryqueue/cowards-game/blob/38f4a83db9298502c12db44cd66d026878803d20/apps/go-backend/live_backend.go#L3240-L3268)).

Because initiative is hash parity and the `:mirror` suffix flips that parity, swapping sides and flipping the initiative side cancel at the entrant level: the original entrant with initiative keeps it in the mirror. Existing coverage asserts only the side swap and suffix ([matchset-service test](https://github.com/roryqueue/cowards-game/blob/38f4a83db9298502c12db44cd66d026878803d20/packages/persistence/src/matchset-service.test.ts#L18-L37)).

v2 Set evidence must prove that each entrant receives each side and each initiative state. This should be represented directly in scenario identity rather than inferred from seed spelling.

## Complexity with weak current value

The following should be removed, narrowed, or made to earn their place:

1. **Persistent immediate-reversal history.** MOVE already updates facing, yet a separate last-successful-direction rule persists across TURNs and creates Strategy boilerplate. A facing-only MOVE experiment can replace it with visible directional commitment.
2. **Cycle-start plus Cycle-end Backstab scans.** For canonically reachable state, every position/facing mutation comes from an Action and can be scanned immediately afterward; cleanup and Contraction remove Soldiers but do not create a new rear relationship.
3. **Twelve mandatory Cycles without a clean stop.** After one Advance, same-facing TURN spam consumes runtime and Chronicle volume without changing state. A legal `HOLD`/`END_ACTIVATION` after Advance is simpler and more honest.
4. **Nominal seed diversity.** If seed means only initial initiative, expose that scenario explicitly.
5. **Duplicate empty arenas.** Distinct labels do not create distinct strategic tests.
6. **Promised-but-unused event vocabulary.** Remove events such as `PUSH_ATTEMPTED` unless consumers need and producers emit them.
