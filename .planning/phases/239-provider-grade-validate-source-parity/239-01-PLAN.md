# Phase 239 Plan 01: Provider-Grade Validate Source Parity

**Created:** 2026-06-14
**Status:** Ready for execution
**Requirements:** CHECKVAL-01, CHECKVAL-02, CHECKVAL-03, CHECKVAL-04, CHECKVAL-05

## Goal

Make Workshop Validate source return the shared `workshop-checker-v1.34` public envelope and use submit-grade runtime-service/provider validation semantics for TypeScript, Python, Rust, and Zig, without moving hostile Strategy execution/build work into web/API/Go.

## Tasks

1. Add shared checker contract/types and normalization helpers outside React.
   - Define checker status, diagnostic categories, actionability, language/provider metadata, artifact/provenance states, availability fields, cache identity, and privacy exclusions.
   - Map existing `StrategyRevisionValidationReport` issues into public checker diagnostics.
   - Redact artifact bytes, provider proof, raw diagnostics, source text, host paths, env/package paths, tokens, DB details, and private runtime internals.

2. Update `/api/workshop/validate`.
   - Accept only TypeScript, Python, Rust, and Zig.
   - Route all four production languages through runtime-service provider validation when required by the checker contract.
   - Build the public checker envelope in app/API, not runtime-service.
   - Schema-guard runtime-service responses before use.
   - Return calm `runtime_service_unavailable`, `toolchain_unavailable`, or `system_unavailable` states instead of generic invalid-source diagnostics for infrastructure failures.

3. Add thin submit/save public normalization.
   - Preserve submit/save as authoritative validation gates.
   - Normalize public unavailable/provider validation messages enough that Validate source and submit/save do not contradict each other.
   - Do not rewrite entry or broad Go account-save policy.
   - Document the TypeScript Go account-save provider-proof gap if it remains unresolved.

4. Test provider parity and privacy.
   - Unit-test checker normalization in the shared helper.
   - Route-test `/api/workshop/validate` for TypeScript, Python, Rust, Zig, missing runtime-service, malformed service response, and invalid provider validation.
   - Verify checker output does not include artifact bytes, provider proof, raw diagnostics, source text, or private runtime markers.
