- **D-14:** Every declared PSRO/double-oracle round targets both the frozen meta-distribution and named strongest or vulnerable pure policies. - **D-17:** Preserve a diverse pure Strategy portfolio separately from every diagnostic mixture. Structural family, strategic-core, lineage, behavior, and response evidence must satisfy the frozen diversity gates; labels and source hashes alone are insufficient.

- **D-20:** Provisional leaders receive the complete frozen automated, model, human, and external development-red-team allocation. ### Pattern 1: Complete immutable snapshot before solving

**What:** Build one expected-cell set from a canonically sorted population; join only terminals whose identity, tuple, candidate, condition, semantic geometry, request, trace and success status all agree; derive one snapshot root only after exact coverage. [VERIFIED: D-07–D-13; current runner/factory patterns]

**When to use:** Before every solver invocation and every downstream report/selection action. [VERIFIED: D-09, D-13]

**Example:**

```ts

```

### Pattern 2: Exact, bounded meta-solver selection

**What:** First commit a synthetic-only numerical spike that compares exact `bigint` rational simplex with a small support-enumeration reference on tiny trusted matrices; accept only a solver that returns identical canonical bytes, including degenerate/tie cases. Then freeze the chosen algorithm/version/pivot rule/tie ordering/normalization in the solver manifest. [ASSUMED: implementation method; CITED: https://proceedings.neurips.cc/paper/7007-a-unified-game-theoretic-approach-to-multiagent-reinforcement-learning.pdf]

**Recommendation:** use two deterministic exact-rational primal LP solves for the finite zero-sum restricted game, with canonical entrant ordering, lexicographic Bland-style entering/leaving ties, normalized non-negative weights summing to `1/1`, and a deterministic infeasible/unbounded/overflow failure disposition. Encode Match scores as integers in half-point units before rational operations. [ASSUMED]

**Numerical spike performed:** a trusted in-memory `bigint` two-by-two rational check produced matching-pennies row/column mixtures `1/2`, and a fractional-boundary matrix mixture `3/5`; no candidate, runtime, Match, oracle, allocation, or artifact was run or mutated. [VERIFIED: local synthetic command executed 2026-09-14]

### Pattern 3: Responses and red-team attempts are ledger events, not annotations

**What:** Record `started` before validation, then retain one terminal disposition for accepted, rejected, invalid, duplicate, legal-but-weak, player violation, system failure, unfilled, or unused work. An accepted counter must create the next declared response target; failed/weak work remains in the same report root. [VERIFIED: D-05, D-14, D-15, D-20; factory ledger patterns]

## Common Pitfalls

### Pitfall 1: Sparse matrix becomes a flattering meta-game

**What goes wrong:** an absent/invalid/system-failed cell is coerced to a draw or zero, letting the solver and report hide the missing counter. [VERIFIED: D-09]

**How to avoid:** exact expected-cell identity set; one terminal per identity; reject solver/report construction unless every cell is successful and identity-consistent. [VERIFIED: D-09; Phase-263 reduction pattern]

### Pitfall 2: Solver determinism is assumed from deterministic Matches

**What goes wrong:** floating reduction, equivalent supports, or pivot order can change the mixture even when cells are deterministic. [ASSUMED]

**How to avoid:** exact rationals, fixed canonical order, explicit pivot/tie policy, golden matrices, adversarial numeric boundaries, and full layout/restart byte tests. [VERIFIED: D-11, D-12; ASSUMED: exact-rational implementation]

### Pitfall 3: Red team is reduced to the convenient channel

**What goes wrong:** Phase 264's unused human/external calibration channel is mistaken for a later waiver. [VERIFIED: Phase 264 context/summary; D-20]

**How to avoid:** require an allocation row and terminal ledger for automated, model, human, and external channels; zero is valid only if a Phase-265 authorization explicitly says so, and would still need to satisfy LEAG-09. [VERIFIED: D-20]

### Pitfall 4: A late counter is presented as an appendix

**What goes wrong:** provisional finalist evidence stays frozen after an accepted development counter. [VERIFIED: D-15]

**How to avoid:** an accepted counter changes the next population snapshot and forces the declared response branch; existing solver output remains historical and cannot be refreshed. [VERIFIED: D-13–D-15]

### Pitfall 5: Robust-pure selection collapses to aggregate win rate

**What goes wrong:** a high average hides a destructive pure response or invariance failure. [VERIFIED: D-18]

**How to avoid:** conjunction over mixture, named pure targets, accepted counters, pure worst case, probe, invariance, legality, privacy, runtime and diversity; otherwise emit the explicit no-finalist disposition. [VERIFIED: D-18, D-19]
