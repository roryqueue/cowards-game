## Finite Crash Diagnostic Seam

The legacy broker's `runLegacy` waits on the signal buffer until its request deadline, then returns synthetic `signal:"SIGKILL"` after terminating its worker. The outer adapter turns any non-null response signal into `SUBPROCESS_SIGNAL`. Therefore that reason code and `native_response` stage alone cannot distinguish broker-synthesized timeout, actual native process signal, worker failure or resource exhaustion. The distinct v117 timing mode uses host envelope frames; switching timing mode is not a diagnosis and would change the frozen runtime path. [CITED: scripts/lib/v1-38-lean-container-match-session.ts:105-145; scripts/lib/v1-38-lean-container-match-session.ts:328]

Recommend a new private broker/adapter seam with a fixed allowlist: origin stage, broker branch, mode, method, request ordinal/root, signal-buffer state, Atomics wait disposition, bounded worker lifecycle counters/exit code, native transport signal enum, termination disposition and finite elapsed buckets. Include an explicit **unknown** where host lifecycle evidence is unavailable. Bind it to allocation/pair/request/source identity, cap bytes, reject extra keys/nonfinite values, and prohibit source/memory/input/stdout/stderr/error-stack text. Do not change guest/host/Match clocks, classification rules or production defaults. Treat cleanup error precedence as a separate demonstrated source defect, not proof of actual crash cause. [CITED: scripts/lib/v1-38-lean-container-match-session.ts; 265-16-CONTINUATION-DECISION-v1.md]

- **Diagnosis overclaim:** `SUBPROCESS_SIGNAL` is not proof of native SIGKILL/OOM or Strategy blame. [CITED: scripts/lib/v1-38-lean-container-match-session.ts; 265-LEAN-BASELINE-RESULT.md]
