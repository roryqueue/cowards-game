## Cross-record field-role joins

1. Allocation → request → entry: source, allocation, request bytes, route/ordinal and HEAD identities agree; allocation predecessor contributes its inherited 36-charge cost context only.
2. Entry → child terminal → result: the entry identity is joined to the child terminal; elapsed/physical cost comes only from the terminal’s bounded summary and the published result’s own counters/root. No child/private error text or compressed/IO evidence is admitted.
3. ROOT closure: independently binds entry, request, allocation, result/terminal/check/ledger identities and supplies the authoritative refused closure class, current=1, cumulative=37, `acceptedCheckAbsent`, `resultAbsent`, `finalReaderClose`, and close-time role fields.
4. Ordinary reader refusal: joins the same allocation/request/source/result identity with an explicitly refused reader outcome. It is not an accepted reader or hold.
5. Carry: supplies survivor identities/allocated bytes and cumulative cost values, but only when all its roots join the ROOT closure and its refusal fields stay non-authorizing.
6. Complete-hold metadata and separate hold-refusal are both pinned as distinct records. The refusal preserves the operator-error event but cannot authenticate the completed-hold role. Neither record creates acceptance.
7. Pair closure: pins cumulative charged/elapsed/debit/survivor prefix and previous/carry/hold roots. It is cost continuity only, not proof that a reader accepted the prefix.

The v1 inventory records the observed bytes/digests only. The executor must recompute them from exact paths in an isolated read-only check before implementing constants; any discrepancy or missing file is a hard blocker, not permission to refresh a pin. No old reader/authenticator or route was run.
