### Complete empirical-game snapshots
- **D-07:** Canonically order each unordered entrant pair by immutable candidate identity, then enumerate the full four-condition entrant-side × entrant-level-initial-initiative policy for every semantically distinct active design arena.

- **D-10:** Completion order, worker count, sharding, restart, and resume cannot affect cell identity, reduction order, payoff bytes, or the snapshot root. Any retry uses the same logical task identity and follows the frozen burn policy.

- **D-11:** Select the exact empirical-game solver only after the required numerical spike. The accepted solver must freeze its algorithm and version, exact numeric representation, canonical entrant ordering, iteration count or convergence schedule, normalization, tie-breaks, and failure behavior.

- **D-14:** Every declared PSRO/double-oracle round targets both the frozen meta-distribution and named strongest or vulnerable pure policies. A response enters the next snapshot only when it passes the frozen legal, independence/clone, novelty, positive-response, runtime, and evidence-completeness admission rule.

- **D-17:** Preserve a diverse pure Strategy portfolio separately from every diagnostic mixture. Structural family, strategic-core, lineage, behavior, and response evidence must satisfy the frozen diversity gates; labels and source hashes alone are insufficient.
- **D-18:** Apply the precommitted robust-pure selection rule to mixture performance, strongest-pure targets, accepted counters, pure-policy worst case, independent probes, invariance, legality, privacy, and runtime evidence. Aggregate win rate cannot substitute for those gates.

- **D-20:** Provisional leaders receive the complete frozen automated, model, human, and external development-red-team allocation. ## Architecture Patterns

### Pattern 1: Gameplay-state continuity across an unrecorded runtime effect

**What:** Keep every transition's machine-before/after hashes as per-record evidence, but compare the prior transition's `afterStateHash` to the next transition's `beforeStateHash` when proving gameplay continuity. The kernel emits an `effect` result carrying a machine with `pendingEffect`; `runCanonicalLabMatch` invokes the provider and resumes the kernel before appending a transition record. State is preserved over this bridge, while machine protocol state intentionally changes. [VERIFIED: packages/engine/src/kernel/step.ts:389-390, packages/engine/src/kernel/step.ts:699-700, packages/strategy-lab/src/runtime-bridge.ts:54-72, packages/engine/src/kernel/validate.ts:768-775]

**When to use:** For the v3 diagnostic's adjacent-record chain in both retention and retained-evidence reopening. Do not reuse a machine-hash adjacency requirement across this protocol boundary unless effect-yield records are also retained—which this amendment does not authorize. [VERIFIED: packages/strategy-lab/src/league/diagnostic-one-cell.ts:367-375, packages/strategy-lab/src/league/diagnostic-one-cell.ts:438-455]

**Example:**

```ts
// Preserve per-record machine hashes; chain the gameplay state across the
// bridge's unrecorded effect yield/resume boundary.
if (previous.afterStateHash !== current.beforeStateHash) {
  return fail("EVIDENCE_TRANSITION_CHAIN")
}
```

[CITED: packages/strategy-lab/src/league/diagnostic-one-cell.ts:367-375]

### Pattern 2: Rooted bounded attempts, not retries of consumed attempts

**What:** Keep one fixed logical task identity (same assessed S01/S03 pair, Smoke semantic geometry, condition, tuple/runtime and strategy revisions), with distinct immutable attempt ordinals/roots and namespaces under one envelope. Burn an attempt before its first live-capable selector; do not recycle a failed, missing, timed-out, or uncertain attempt. Before each next ordinal, require the previous attempt's retained terminal, exact-root verification, complete cleanup, and unchanged historical roots; then perform a fresh admitted preflight. The envelope records every charge and outcome, including safe no-start/preflight-denial dispositions, without allowing an attempt to count twice. [CITED: 265-CONTEXT.md D-01, D-02, D-05, D-10; 265-12-PLAN.md; direct user authorization relayed by orchestrator]

**Implementation shape:** One new shared policy/harness consumes the exact approval message and fixed maximum (5), common 240000/600000/30000 ms bounds, unchanged current-rules S01/S03 Smoke target, old v3 roots, and source-gate root. Per-attempt records bind the envelope root, ordinal, logical task root, fresh allocation/preflight/run roots, charge, terminal, cleanup, and verifier disposition. Execute at most one attempt at a time. No five cloned source gates, mutable “latest” pointer, unused-slot conversion into extra work, or inferred approval. [CITED: direct user authorization relayed by orchestrator; 265-CONTEXT.md D-01, D-05, D-10; 265-12-PLAN.md]

Keep historical result exactly `unknown_internal`. [CITED: 265-12-SOURCE-DIAGNOSIS.md; 265-12-SUMMARY.md]
3. **Replacing machine integrity with weaker checks:** The adjacent machine hashes differ at a legitimate effect/resume boundary; replacing the chain with state hashes must not remove exact row schema, per-record hash shape, terminal-last, accounting, outcome/events, rooted-chunk, and orphan checks. Add positive effect-handoff and negative altered-state-chain fixtures. [VERIFIED: packages/strategy-lab/src/league/diagnostic-one-cell.ts:367-375, 430-481; packages/strategy-lab/src/runtime-bridge.ts:54-72]
4. **Exposing underlying error text:** Do not retain raw exceptions, Strategy output, source, request payload, or private runtime detail. Add only exact safe allowlist entries for stable repository error codes; unknown values remain `unknown_internal`. The historical diagnosis lists omitted stable retention/ledger codes but does not prove any caused the old failure. [CITED: packages/strategy-lab/src/league/diagnostic-one-cell.ts:45-57; 265-12-SOURCE-DIAGNOSIS.md]
5. **Running slots concurrently or without fresh preflight:** Attempt budget, host condition, and cleanup state are serial. Require a fresh admitted preflight for each new live attempt; any failed/uncertain selector latch, charge, publication, verification, or cleanup must fail closed rather than be replayed.
