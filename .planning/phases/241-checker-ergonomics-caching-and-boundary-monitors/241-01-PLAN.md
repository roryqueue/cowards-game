# Phase 241 Plan 01: Checker Ergonomics, Caching, and Boundary Monitors

**Created:** 2026-06-14
**Status:** Ready for execution
**Requirements:** CHECKERG-01, CHECKERG-02, CHECKERG-03, CHECKERG-04

## Goal

Make Rust/Zig validation realistic during editing with debounce, stale state, in-flight coalescing, and ephemeral cache behavior, while adding boundary monitors that prevent Strategy execution/TinyGo/provider-ownership drift.

## Tasks

1. Add route-level coalescing/cache.
   - Add short-lived in-memory in-flight coalescing and TTL cache for `/api/workshop/validate`.
   - Key by source format, provider id, source hash/bytes, provider contract version, runtime ABI version, validation policy, and toolchain/provider compatibility metadata where available.
   - Do not persist checker results or let cache become authoritative evidence.
   - Submit/save must continue to revalidate.

2. Improve client stale-state behavior.
   - Preserve prior checker result while a new source/format is pending.
   - Clearly mark stale results and prevent stale results from enabling submit/save.
   - Avoid clearing useful diagnostic context on every edit.

3. Add boundary monitors.
   - Prove no Strategy execution or hostile compiler/runtime ownership moved into web/API/Go.
   - Prove TinyGo remains absent from production Workshop validation, submit/save, entry, result, replay, and public evidence surfaces.
   - Prove checker responses are schema-validated data before UI/use.

4. Test ergonomics and boundaries.
   - Unit/route-test coalescing/cache reuse and invalidation.
   - UI helper tests for stale/checking/ready/unavailable/failed states.
   - Add or extend boundary monitor tests.

## Completion Criteria

- Rust/Zig checker calls are paced by debounce plus coalescing/cache.
- Cache identity cannot cross language/provider/source/policy/runtime ABI/toolchain boundaries.
- Stale results are visible but not treated as current readiness.
- Boundary monitors cover no Strategy execution in web/API/Go, TinyGo hidden, provider ownership, and schema-validated checker responses.
