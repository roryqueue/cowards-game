# Phase 240 Plan 01: Language Diagnostic UX and Availability States

**Created:** 2026-06-14
**Status:** Ready for execution
**Requirements:** CHECKDIAG-01, CHECKDIAG-02, CHECKDIAG-03, CHECKDIAG-04, CHECKDIAG-05

## Goal

Make Python, Rust, and Zig checker diagnostics actionable, public-safe, and language-specific while keeping React components display-only and unavailable states calm.

## Tasks

1. Extend shared checker mapping.
   - Distinguish Python policy/capability, forbidden import, package/dependency, syntax/build, provenance, runtime-service unavailable, timeout/limit, and invalid output/schema categories.
   - Distinguish Rust compile, artifact/provenance, forbidden WASI/import, runtime-service, toolchain unavailable, timeout/limit, and invalid output/schema categories.
   - Distinguish Zig compile, artifact/provenance, forbidden WASI/import, no-std/helper misuse, runtime-service, toolchain unavailable, timeout/limit, and invalid output/schema categories.
   - Include line/column/reference only from structured public-safe fields.

2. Improve Workshop display.
   - Render normalized checker diagnostics and actionability from the shared contract.
   - Show calm runtime-service/toolchain unavailable copy with language-specific next step.
   - Remove public/default display of `forbiddenPatterns` and other privacy-sensitive raw detail from advanced Workshop details.
   - Keep TypeScript practical UX quality intact.

3. Test diagnostic UX and privacy.
   - Unit-test category/actionability mapping for representative Python/Rust/Zig issues.
   - Unit-test unavailable-state copy and submit-blocking behavior.
   - UI helper tests should prove React components render normalized data, not raw provider/runtime internals.
