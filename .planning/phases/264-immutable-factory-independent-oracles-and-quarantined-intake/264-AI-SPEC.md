## 1. System Classification

**System Type:** Code automation: offline deterministic program synthesis from frozen bundles.

**Description:**
A private provider-neutral TypeScript channel admits immutable model request/response bundles and explicit hostile source into the shared supervised factory. Model authoring occurs outside the deterministic runner; the runner never calls a model or network. Claims require genuine provenance and empirical independence, not labels.

**Critical Failure Modes:**
1. Executing generated source or live inference in the coordinator or Match runner.
2. Forging provider/model provenance or silently substituting a different identity.
3. Leaking private Strategy or holdout payloads, or counting clones as independent evidence.

### What Domain Experts Evaluate Against

Dimension: Legal-information-only action decisions
Good: Every emitted choice is reproducible from the canonical information set and obeys literal legality; canonical objective/StrategyMemory/SoldierMemory inputs remain within their defined boundary, while privileged teacher/other-player or hidden state does not reach the student.
Bad: A source reads privileged state, invents an illegal action, or uses a fallback result after a boundary failure.
Stakes: Critical.
Source: `264-CONTEXT.md` D-03, D-16; `packages/strategy-lab/src/planner/information-boundary.test.ts`.

Dimension: Genuine strategic-core independence
Good: Tactical, teacher/student, and model lanes own distinct selectors/logic and have only the audited non-strategic helper allowlist; receipts cover dependency, authorship, source, behavior, correlation, clone, and failure evidence.
Bad: Shared scorer/search/prompt/learned parameter is hidden behind package names, or independence is asserted from labels/processes alone.
Stakes: Critical.
Source: `264-CONTEXT.md` D-14–D-19; Phase 264 research on PSRO correlation.

Dimension: Clone and correlation judgment
Good: Six frozen fingerprints detect semantic rewrites, shared selectors, near-identical behavior, and response correlation; borderline cases remain `unresolved` and do not count.
Bad: Cosmetic rewrites, parameter changes, or a source hash are treated as diversity, or thresholds are tuned on league/holdout outcomes.
Stakes: High.
Source: `264-CONTEXT.md` D-11–D-13; `264-RESEARCH.md`.

Dimension: Hostile-source and runtime disposition
Good: Explicit source is admitted by schema and executed only by the existing supervised bridge; success, player violation, and system failure remain distinct.
Bad: Coordinator/web/API/Go executes source, direct imports or `vm` are used, or system failure is scored as gameplay.
Stakes: Critical.
Source: `AGENTS.md`; `packages/strategy-lab/src/runtime-bridge.ts`; `264-CONTEXT.md` D-03–D-05.

Dimension: Immutable provenance and honest failed attempts
Good: Exact source/bundle/provider identity, lineage, inputs, budget, validation, and terminal disposition are content-addressed; invalid, rejected, duplicate, retried, weak, and system-failed attempts remain charged.
Bad: `latest`/upsert overwrites evidence, provider identity is silently substituted, or only successful attempts are retained.
Stakes: High.
Source: `264-CONTEXT.md` D-02, D-04, D-07–D-10, D-20; SLSA provenance checklist in `264-RESEARCH.md`.

## 2. Framework Decision

**Selected Framework:** Native TypeScript strict frozen-bundle adapter; no AI orchestration framework.

**Version:** Existing repository TypeScript 6.0.3 and Zod 4.4.3; preserve lockfile-pinned dependencies.

**Rationale:**
The locked channel needs bounded validation and immutable artifacts, not live agent orchestration. Reuse the private lab's identity, supervision and trace machinery without new hosted infrastructure.

**Alternatives Considered:**

| LangChain.js | Unnecessary live-orchestration abstraction for frozen local bundles; reconsider only under future explicit scope. |

**Vendor Lock-In Accepted:** No. An attempt binds its exact provider/model/version; provider-neutral does not mean interchangeable identities.

### Entry Point Pattern
```ts
export function admitFrozenAttempt(bytes: Uint8Array) {
  // Apply the separately frozen bundle byte cap before parsing.
  const admitted = admitCanonicalJsonBytes(bytes, {
    profile: "canonical-manifest", operation: "require-canonical",
  })
  if (!admitted.ok) throw new TypeError("FACTORY_BUNDLE_INVALID")
  const bundle = FactoryModelBundleSchema.parse(admitted.value)
  // The strict schema checks exact native lane, provenance, budgets and source byte caps.
  return freezeLabValue({ bundle, root: labRoot("factory-model-bundle-v1", bundle) })
}

// A separately frozen offline producer may call models outside the deterministic
// runner. The runner consumes data and executes source only via existing supervision.
```

### Key Abstractions
| Concept | What It Is | When You Use It |
|---------|-----------|-----------------|
| Frozen request/response bundle | Content-addressed, immutable provider/model/settings and output record | Before any replay or source admission |
| Zod boundary schema | Runtime validation of unknown JSON and failure classification | At every bundle, source, and response boundary |
| Native source lane | Exact emitted source plus declared language/runtime tuple | Revalidate and execute without translation |
| Supervised runtime adapter | Hostile execution with player-violation/system-failure separation | After admission; never in coordinator/runner |
| Append-only attempt ledger | Records successes and all failed/rejected/duplicate attempts | Every attempt, including retries |

### Common Pitfalls
1. Treating `readonly` as deep runtime immutability: clone/freeze or canonicalize before hashing; readonly is primarily a type-checking constraint.
2. Trusting a cast (`as Bundle`) or parsed source: it bypasses runtime validation and can admit forged provenance or malformed output.
3. Calling a provider from the runner: it breaks deterministic replay and makes model identity/budget accounting unverifiable.
4. Reusing a mutable `latest` pointer: correction or provider drift changes historical evidence; address immutable content roots only.
5. Running generated source directly in Node: source is hostile; route every language through the existing supervised boundary and retain its disposition.

## 4. Implementation Guidance

**Model Configuration:**
No provider/model has yet been selected for actual participation. A separately frozen offline producer outside the runner records exact provider, model, version, settings, prompt/context hashes, token counts, and response bytes. The infrastructure accepts genuine bundles without making live runner calls. Missing or drifting identity is a blocked attempt, never substitution.

**Core Pattern:**
Validate unknown bundle data with the canonical Zod schema, derive a content hash from canonical bytes, preserve exact native source, then pass source only to the existing supervised adapter. Keep request, response, provenance, validation result, fingerprints, resource use, and disposition in one append-only ledger record.

**Tool Use:**
No hosted tools, tracing service, network, or live model calls. Reuse private JSON traces and Vitest assertions. Any external/model authoring process writes a frozen bundle; the runner reads it as data and cannot invoke it.

**State Management:**
Use immutable content-addressed bundle/candidate/attempt roots and lineage edges. Never mutate accepted records or use `latest`; retries and metadata corrections create new artifacts. Persist failures and duplicates as charged evidence.

**Context Window Strategy:**
The runner has no context window. The producer must record exact prompt/context bytes or hashes and explicit token limits; truncate/summarise only before bundling and record that transformation. Never disclose holdout, objectives, private memories, or evaluator state.

## 4b. AI Systems Best Practices

> Written by `gsd-ai-researcher`. Cross-cutting patterns every developer building AI systems needs — independent of framework choice.

### Structured Outputs with Pydantic

Pydantic is informational guidance for an external producer only, not a repository dependency or execution lane. Canonical admission remains Zod.

```python
from pydantic import BaseModel, Field

class ExternalBundle(BaseModel):
    source: str
    provider: str
    model: str
    response_sha256: str = Field(pattern=r"^[0-9a-f]{64}$")
```

This intentionally abbreviated external-producer example is not a complete admission schema. The repository still requires every frozen provenance and budget field. Validation failure is a charged invalid attempt; retry is allowed only when explicitly present in that channel's frozen opportunity allocation, never automatically or with an invented retry count.

### Async-First Design

The adapter and supervised task runner may be async for IO; canonical admission/hashing and game transitions remain deterministic, with no network or system time in engine logic. Await complete producer responses before validation and hashing. Do not confuse async supervision with permission for live model calls inside the runner.

### Prompt Engineering Discipline

Keep producer system instructions separate from task/context data; hash both and record versions. Use small fixed few-shot examples only when frozen in the bundle (dynamic retrieval changes provenance). Set explicit output/token limits; unbounded generation is not admissible.

### Context Window Management

This is a frozen-bundle synthesizer, not RAG or conversation memory. Bound context before the call, record included/excluded context hashes and truncation, and reject bundles that omit required provenance. The runner receives no hidden context and no holdout material.

### Cost and Latency Budget

Attribute provider-reported input/output tokens and wall time to every attempt; unavailable accounting is a failure, not zero cost. Exact request-hash caching may reuse an immutable response; semantic caching is out of scope unless its key and collision policy are frozen. If a producer routes cheap models for classification/summarisation, record each sub-call and charge failures/retries to the same attempt budget.

## 6. Guardrails

### Online (Real-Time)

| Guardrail | Trigger | Intervention |
|-----------|---------|--------------|
| Canonical provenance admission | Non-canonical/oversize/incomplete bytes, identity drift, hash/root mismatch, or mutable address | Block; append charged invalid/blocked attempt with no substitution. |
| Execution boundary | Direct import/eval/`vm`/runner provider call, forbidden lane, hidden input, or missing supervised disposition | Block before execution; retain system/boundary failure, never gameplay fallback. |
| Clone/intake quarantine | Forbidden strategic dependency, missing fingerprint/receipt, `unresolved` clone/correlation, incomplete disclosure/provenance/conflict | Quarantine and retain charged disposition; do not count toward any gate. |

### Offline (Flywheel)

| Metric | Sampling Strategy | Action on Degradation |
|--------|------------------|----------------------|
| Admission/identity failures and root mismatches | Every private attempt | Stop affected lane; preserve receipt and correct only through a new artifact. |
| Three-way ledger completeness and resource-field presence | Every terminal attempt | Fail the contract suite; unresolved evidence cannot advance. |
| Fingerprint/receipt completeness and unresolved rate | Every calibration candidate; development-only corpus | Quarantine affected candidates; calibrate/freeze cutoffs only under a separately approved fresh protocol. |
| Disclosure/intake denials | Every intake packet | Keep private denial record; no public or production projection. |

## 7. Production Monitoring

**Tracing Tool:** Content-addressed private JSON attempt/validation/runtime traces; no hosted observability service and no live model tracing.

**Key Metrics to Track:**
Development-only: admission block reason; immutable-root mismatch; terminal-ledger completeness; supervised success/player-violation/system-failure counts; fingerprint/receipt completeness and unresolved quarantine count; missing resource accounting. Record actual supervised calibration Match resources and offline producer resources when separately predeclared and performed. No production traffic or Phase265 league result is claimed by this design.

**Alert Thresholds:**
Any root/provenance mismatch, direct-execution/provider-call signal, prohibited disclosure, missing terminal disposition, or missing resource field is a fail-closed test failure. Any unresolved clone/correlation or unavailable exact provider identity is a block, not a pass. No numeric clone cutoff or alert volume is set before the authorized development calibration.

**Smart Sampling Strategy:**
There is no human-review sampling claim. Retain and inspect every private failed, rejected, duplicate, drifted, system-failed, and unresolved receipt in deterministic test output; genuine external/model records are included only when they exist under an authorized frozen protocol.
