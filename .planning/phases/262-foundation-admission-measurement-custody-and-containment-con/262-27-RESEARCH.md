### Closed control-channel v2

Use a dedicated bounded control pipe separate from stdout result bytes. The state machine should accept exactly these ordered states: `spawned` (parent-observed), one canonical `ready` frame from the child, then exactly one canonical terminal frame. The terminal is either `success` (stdout result must separately validate) or one finite failure family. Missing, duplicate, out-of-order, noncanonical, oversized, invalid UTF-8, unknown-key, unknown-code, stderr-contaminated, signaled, or late frames fail closed. [RECOMMENDATION]

The minimal public-safe failure families should be:

| Family | Exact meaning | Must not contain |
|---|---|---|
| `CHILD_BOOTSTRAP_FAILED` | Process spawned but never emitted the exact `ready` frame before exit/timeout. [RECOMMENDATION] | module path, loader text, cwd, environment, stack |
| `CHILD_TRANSPORT_FAILED` | Spawn/control/result framing, exit/signal, canonical-byte, message-count, or stdout-result transport failed after the applicable parent state. [RECOMMENDATION] | status number, signal, stderr, bytes, host/process identifiers |
| `RUNTIME_EXECUTION_FAILED` | The child reached ready state and an unexpected exception crossed the exact authority/runtime execution boundary. [RECOMMENDATION] | runtime diagnostic/code unless already an approved existing public runtime code, Strategy/Match/source/memory/objective data |
| `SHARD_COORDINATION_FAILED` | Payload validation, inventory selection, attempt join, or result assembly/serialization failed outside runtime execution. [RECOMMENDATION] | attempt payloads, repo paths, inventory content, private result data |

Existing resource-policy reasons (`RESOURCE_*`), cleanup failure, parent interruption, and parent exception remain orthogonal scheduler classifications; do not rename or weaken them. [RECOMMENDATION]

### Pure stage ownership

Refactor the current catch-all into explicit pure/typed boundaries: decode and validate a closed request; resolve exact inventory/attempt identities; invoke an injected runtime executor; validate and encode the result; emit the terminal control frame. Each boundary catches only its own exception and maps it to one failure family. The production entry supplies real functions; tests supply deterministic functions directly. Do not add environment switches, global symbols, caller-provided authority bypasses, or production-only test hooks. [RECOMMENDATION; informed by `262-24-REVIEW-FIX.md`]

### Parent reduction

The production parent must consume the child-emitted control frames. A passing test is not sufficient if production still constructs `{schemaVersion,failureCode}` locally as it does today. The batch stop reason should retain a single public-safe initiating family, while cancelled siblings remain cancelled and all allocated attempts remain charged. Conflicting initiating families, multiple failed children without a unique canonical first terminal, or malformed ordering should reduce to `CHILD_TRANSPORT_FAILED` or a separate existing integrity stop, never an arbitrary first message. [RECOMMENDATION]
