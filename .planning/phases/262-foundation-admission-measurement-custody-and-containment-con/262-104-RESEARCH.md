## Common Pitfalls

### Pitfall 1: Resolving the First Path-History Commit Without Blob Filtering

**What goes wrong:** A later rewrite or duplicate introduction can be selected merely because it is newest. [VERIFIED: general Git topology inference]

**How to avoid:** Filter candidates by all three exact tree entries, require exact three-path introduction, and require one match only. [VERIFIED: recommended architecture]

### Pitfall 2: Forgetting Source Ancestry After Removing Direct-Parent Equality

**What goes wrong:** Any unrelated historical trio could be accepted if only blobs match. [VERIFIED: threat analysis]

**How to avoid:** Require both `reviewedSourceCommit <= publicationCommit` and `publicationCommit <= current HEAD`; also reauthenticate the reviewed source blobs and no-later-rewrite claim. [CITED: https://git-scm.com/docs/git-merge-base]

### Pitfall 3: Binding the Seal to the Trio Commit Instead of the Plan-105 Closure

**What goes wrong:** Revised Plan 92 cannot be a direct child of the current reviewed correction closure, or later source/review bytes are omitted. [VERIFIED: dependency topology inference]

**How to avoid:** Keep historical publication identity inside the source/review root while capturing the current Plan-105 summary closure as the seal pair's direct parent immediately before publication. [VERIFIED: recommended architecture]

### Pitfall 4: Adding CLI Labels Without Native Behavior

**What goes wrong:** Plan 92 references a mode that parses but still cannot atomically/no-replace publish or verify the pair. [VERIFIED: current missing-mode gap]

**How to avoid:** Route publication to `publishV138RetryV3NativePair`, and give checker tests committed disposable Git topology rather than mocked return values only. [VERIFIED: recommended architecture]

### Pitfall 5: Synthetic Tests Accidentally Touch Canonical Destinations

**What goes wrong:** Source review creates the real seal/envelope before Plan 92. [VERIFIED: threat analysis]

**How to avoid:** Snapshot canonical destinations and refs, run actual modes only in a no-local disposable clone/temp repository, remove it on all exits, then prove equality and absence. [VERIFIED: existing Plan-103 pattern]

### Pitfall 6: Partial Native Publication on Failure

**What goes wrong:** One member or an intent file survives a crash/error. [VERIFIED: pair-publication threat model]

**How to avoid:** Reuse existing native pair helper and retain its crash-boundary/recovery tests; Plan 104 adds adapter-level pre-existing-destination, forced failure, cleanup, and retry rejection tests. [VERIFIED: existing helper capabilities; recommendation is an inference]
